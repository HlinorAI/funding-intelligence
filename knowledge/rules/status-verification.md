# Status verification

The knowledge base is a dated snapshot. Statuses are routing hints, not live truth.

Before recommending `APPLY`:

1. Open the official program page.
2. Open the actual application/intake endpoint, not only a marketing page.
3. Confirm mechanism, eligibility, deadline/window, and current terms.
4. Treat each `pathway` as a separate route. A program brand, ecosystem page,
   or historical funding relationship is not evidence that every cohort, RFP,
   retroactive route, or credits route is currently open.
5. Record the check date and link.
6. If official pages conflict, prefer `actual intake endpoint > current official announcement > docs > marketing page > aggregator`.

If the source is more than seven days old, or a deadline/season is involved, keep the card in verification until checked again. The runtime enforces the seven-day source-freshness gate after a card claims its status is verified; a stale snapshot cannot reach `NOW` merely because the legacy `needs_verification` flag is false. Never infer an open program from a large treasury, old article, stale landing page, or past funded cohort.
